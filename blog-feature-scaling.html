Understanding Feature Scaling: Standardization vs. Normalization

Features rarely arrive on the same scale. House size might run into the thousands while the number of bedrooms stays under ten. This article explains why that matters and how to choose between the two most common fixes.

4 min read

Why scaling matters

Many algorithms compare or combine features numerically. If one feature ranges from 0 to 100,000 and another from 0 to 5, the large one dominates any distance calculation, and gradient descent takes a long, zig-zag path to the minimum.

Scaling usually matters for:

  • Distance-based models: k-nearest neighbours, k-means, and support vector machines.
  • Gradient-descent models: logistic regression, neural networks, and regularised regression such as Ridge and Lasso.
  • Projection methods: PCA, which looks for directions of maximum variance.

Tree-based models (decision trees, random forests, gradient boosting) split on thresholds within a single feature, so they are largely unaffected. Ordinary least squares also gives the same predictions with or without scaling, but its coefficients only become comparable across features once the features share a scale.

Standardization (z-score)

Standardization shifts each feature to a mean of 0 and rescales it to a standard deviation of 1.

z = (x − μ) / σ

The result is not bounded to a fixed range. Standardization is a common default because it keeps the shape of the distribution and does not squeeze most values into a narrow band when a few extreme values exist.

Normalization (min-max scaling)

Min-max scaling maps the smallest value to 0 and the largest to 1.

x′ = (x − min) / (max − min)

The output range is guaranteed for the data used to fit the scaler, which is handy for inputs that are naturally bounded, such as pixel intensities. The weakness is sensitivity to outliers: one extreme value stretches the range and compresses everything else.

Terminology. "Normalization" sometimes also means scaling each row to unit length (scikit-learn's Normalizer). In this article it means min-max scaling.

Take the values 10, 20, 30, 40 and 50. The mean is 30 and the (population) standard deviation is √200 ≈ 14.14.

Scaling in scikit-learn

Both scalers follow the same pattern: fit learns the statistics, transform applies them.

Python
import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler, MinMaxScaler

# Feature 1: house size (sq ft). Feature 2: number of bedrooms.
X = np.array([
    [850, 2], [1200, 3], [1500, 3], [1750, 4],
    [2100, 4], [2400, 4], [3000, 5], [3400, 5],
], dtype=float)

X_train, X_test = train_test_split(X, test_size=0.25, random_state=42)

# Standardization: learn mean and std from the training data only
std_scaler = StandardScaler().fit(X_train)
X_train_std = std_scaler.transform(X_train)
X_test_std = std_scaler.transform(X_test)

# Min-max normalization: learn min and max from the training data only
mm_scaler = MinMaxScaler().fit(X_train)
X_train_mm = mm_scaler.transform(X_train)
X_test_mm = mm_scaler.transform(X_test)

print(X_train_std.mean(axis=0))   # close to [0, 0]
print(X_train_std.std(axis=0))    # [1, 1]
print(X_train_mm.min(axis=0))     # [0, 0]
print(X_train_mm.max(axis=0))     # [1, 1]

Notice that the scalers are fitted on the training rows only. The test rows are transformed with the training statistics, so a test value can legitimately fall outside the 0 to 1 range after min-max scaling.

Avoid data leakage with a pipeline

If you fit a scaler on the full dataset before splitting, information about the test set leaks into training and your evaluation looks better than it should. A pipeline makes the correct order automatic, including inside cross-validation.

Python
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)

# The scaler is re-fitted on the training part of every fold, so nothing leaks
model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
scores = cross_val_score(model, X, y, cv=5)
print(scores.mean())

Which one should you use?

AspectStandardizationMin-max normalization
Formula(x − mean) / std(x − min) / (max − min)
Output rangeUnbounded, centred on 00 to 1 on the fitting data
OutliersAffect mean and std, but do not squash other values as sharplyOne outlier compresses all other values
Typical useLinear and logistic regression, SVM, PCA, k-NNNeural networks, bounded inputs such as pixels

If your data has heavy outliers, RobustScaler (based on the median and interquartile range) is worth trying. When in doubt, start with standardization and compare validation scores.

Common mistakes

  • Fitting the scaler on all the data before the train/test split.
  • Using different scalers (or forgetting the scaler) at prediction time. Save the whole pipeline instead.
  • Scaling one-hot encoded columns for no reason. It is harmless but usually unnecessary.
  • Scaling the target without converting predictions back to the original units.

Takeaway. Scale when the algorithm is sensitive to feature magnitude, fit on training data only, and let a pipeline enforce that for you.
