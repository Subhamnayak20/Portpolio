Medallion Architecture: Bronze, Silver and Gold Layers in Microsoft Fabric

The medallion architecture organises a lakehouse into layers of increasing quality. It is a common pattern in Microsoft Fabric data engineering work.

2 min read Draft

Draft. This article explains the general pattern. Before publishing, add examples from your own pipelines and what you learned from them.

The three layers

LayerContentsTypical operations
BronzeRaw data copied from the source, mostly unchangedIngest, add load timestamp or source name
SilverCleaned, validated and conformed dataFix data types, remove duplicates, handle nulls, join reference data
GoldCurated tables shaped for analyticsAggregate, build dimensional models, define business metrics

Why use layers?

  • Traceability: raw data is kept, so you can rebuild later layers if the logic changes.
  • Separation of concerns: ingestion, cleaning and business logic live in different steps that are easier to test.
  • Reuse: several reports can read the same gold tables instead of repeating transformations.

In Microsoft Fabric

A common setup is a lakehouse (or one per layer) that stores Delta tables, with data pipelines or notebooks moving data from one layer to the next. Fabric's SQL analytics endpoint and Power BI can then read the gold tables.

A minimal PySpark sketch

This sketch is meant to be run in a Fabric notebook attached to a lakehouse, where a spark session already exists. The file path and column names are placeholders.

Python
from pyspark.sql import functions as F

# Bronze: land the raw file as a Delta table, unchanged
bronze = (
    spark.read.format("csv")
    .option("header", True)
    .load("Files/raw/orders.csv")        # path inside the attached lakehouse
)
bronze.write.mode("overwrite").format("delta").saveAsTable("bronze_orders")

# Silver: fix types, remove duplicates and unusable rows
silver = (
    spark.read.table("bronze_orders")
    .dropDuplicates(["order_id"])
    .withColumn("order_date", F.to_date("order_date"))
    .withColumn("amount", F.col("amount").cast("double"))
    .filter(F.col("amount").isNotNull())
)
silver.write.mode("overwrite").format("delta").saveAsTable("silver_orders")

# Gold: business-ready aggregate for reporting
gold = (
    spark.read.table("silver_orders")
    .groupBy("order_date")
    .agg(F.sum("amount").alias("daily_revenue"))
)
gold.write.mode("overwrite").format("delta").saveAsTable("gold_daily_revenue")

Design notes

  • Decide how each layer is refreshed: full overwrite (simple) or incremental (efficient for large data).
  • Add data quality checks between layers, such as row counts and null checks.
  • Name tables consistently, for example bronze_orders, silver_orders, gold_daily_revenue.
