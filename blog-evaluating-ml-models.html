Evaluating Machine Learning Models

A model that scores well on the data it was trained on tells you very little. This article covers the habits and metrics that give a trustworthy picture of performance.

3 min read

Start with data the model has not seen

Split the data into a training set, used to fit the model, and a test set, used once at the end to estimate real-world performance. If you tune settings, add a validation set (or use cross-validation) so the test set stays untouched. For classification, use stratify=y so each split keeps the same class proportions.

Classification: more than accuracy

Predictions fall into four groups, shown in a confusion matrix:

Predicted positivePredicted negative
Actually positiveTrue positive (TP)False negative (FN)
Actually negativeFalse positive (FP)True negative (TN)
MetricFormulaAnswers the question
Accuracy(TP + TN) / allHow often is the model right overall?
PrecisionTP / (TP + FP)When it predicts positive, how often is it correct?
RecallTP / (TP + FN)Of the real positives, how many did it find?
F1 score2 · P · R / (P + R)A single balance of precision and recall
ROC AUCArea under the ROC curveHow well does it rank positives above negatives across thresholds?

The accuracy trap. Imagine 1,000 transactions of which 20 are fraudulent. A model that always predicts "not fraud" scores 98% accuracy and catches none of the fraud (recall = 0). On imbalanced data, look at precision, recall and F1.

Example in scikit-learn

Python
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report, confusion_matrix, roc_auc_score
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42
)

model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
model.fit(X_train, y_train)

y_pred = model.predict(X_test)
print(confusion_matrix(y_test, y_pred))
print(classification_report(y_test, y_pred))

proba = model.predict_proba(X_test)[:, 1]   # probability of class 1
print("ROC AUC:", roc_auc_score(y_test, proba))

Cross-validation

A single split can be lucky or unlucky. K-fold cross-validation trains and tests on several different splits and reports the average and spread. Putting the preprocessing inside a pipeline keeps each fold honest.

Python
from sklearn.model_selection import cross_val_score

# Uses the pipeline and data from the previous example
scores = cross_val_score(model, X, y, cv=5, scoring="f1")
print("F1 per fold:", scores)
print("Mean:", scores.mean(), "Std:", scores.std())

Regression metrics

MetricWhat it tells you
MAE (mean absolute error)Average size of the errors, in the target's units
MSE (mean squared error)Average of squared errors; penalises large errors heavily
RMSESquare root of MSE, back in the target's units
R²Share of target variance explained; 1 is perfect, 0 matches predicting the mean, and it can be negative
Python
import numpy as np
from sklearn.datasets import make_regression
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score
from sklearn.model_selection import train_test_split

X, y = make_regression(n_samples=300, n_features=5, noise=15, random_state=0)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=0)

pred = LinearRegression().fit(X_train, y_train).predict(X_test)

print("MAE: ", mean_absolute_error(y_test, pred))
print("RMSE:", np.sqrt(mean_squared_error(y_test, pred)))
print("R^2: ", r2_score(y_test, pred))

Overfitting and underfitting

PatternMeaningThings to try
High training score, much lower validation scoreOverfitting: the model memorised noiseMore data, simpler model, regularisation, fewer features
Low scores on bothUnderfitting: the model is too simple or the features are weakBetter features, a more flexible model
Similar, good scores on bothA reasonable fitConfirm once on the untouched test set

Evaluation checklist

  • Hold out a test set and use it only once.
  • Choose metrics that match the cost of each kind of mistake.
  • Compare against a simple baseline, such as predicting the majority class or the mean.
  • Use cross-validation for a more stable estimate.
  • Keep preprocessing inside the pipeline to avoid leakage.
