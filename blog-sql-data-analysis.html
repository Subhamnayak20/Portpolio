SQL Techniques for Data Analysis

Most analysis questions come down to a handful of SQL patterns. These examples use a small sales schema and standard SQL, with PostgreSQL syntax where dialects differ.

3 min read

The sample tables

All queries below assume two tables. They are examples; adapt the names to your own data.

TableColumns
ordersorder_id, customer_id, order_date, category, amount
customerscustomer_id, name, city

1. Aggregate, then filter groups with HAVING

WHERE filters rows before grouping. HAVING filters the groups after aggregation.

SQL
-- Revenue by category, keeping only categories above 10,000
SELECT
    category,
    COUNT(*)                AS orders,
    SUM(amount)             AS revenue,
    ROUND(AVG(amount), 2)   AS avg_order_value
FROM orders
GROUP BY category
HAVING SUM(amount) > 10000
ORDER BY revenue DESC;

2. Bucket values with CASE

CASE turns a numeric column into labelled segments you can group and count.

SQL
SELECT
    CASE
        WHEN amount >= 500 THEN 'High'
        WHEN amount >= 100 THEN 'Medium'
        ELSE 'Low'
    END AS order_band,
    COUNT(*) AS orders
FROM orders
GROUP BY
    CASE
        WHEN amount >= 500 THEN 'High'
        WHEN amount >= 100 THEN 'Medium'
        ELSE 'Low'
    END;

3. Build queries in steps with a CTE

A common table expression names an intermediate result so the final query stays readable. Here it computes monthly revenue, then uses LAG to compare each month with the previous one.

SQL
WITH monthly AS (
    SELECT
        DATE_TRUNC('month', order_date) AS month,
        SUM(amount)                     AS revenue
    FROM orders
    GROUP BY DATE_TRUNC('month', order_date)
)
SELECT
    month,
    revenue,
    LAG(revenue) OVER (ORDER BY month) AS prev_revenue,
    ROUND(
        100.0 * (revenue - LAG(revenue) OVER (ORDER BY month))
        / NULLIF(LAG(revenue) OVER (ORDER BY month), 0),
        1
    ) AS growth_pct
FROM monthly
ORDER BY month;

Dialect note. DATE_TRUNC('month', ...) is PostgreSQL. MySQL uses DATE_FORMAT, and SQL Server 2022 and later offers DATETRUNC. NULLIF avoids a divide-by-zero error for the first month.

4. Running totals with window functions

A window function adds a calculation across related rows without collapsing them into one row per group. SUM(SUM(amount)) OVER (...) sums the daily totals cumulatively.

SQL
SELECT
    order_date,
    SUM(amount)           AS daily_revenue,
    SUM(SUM(amount)) OVER (ORDER BY order_date) AS running_revenue
FROM orders
GROUP BY order_date
ORDER BY order_date;

5. Top N per group with ROW_NUMBER

To find each category's three biggest customers, rank within a partition, then filter on the rank in an outer query.

SQL
SELECT customer_id, category, spend
FROM (
    SELECT
        customer_id,
        category,
        SUM(amount) AS spend,
        ROW_NUMBER() OVER (
            PARTITION BY category
            ORDER BY SUM(amount) DESC
        ) AS rn
    FROM orders
    GROUP BY customer_id, category
) AS ranked
WHERE rn <= 3
ORDER BY category, rn;

6. Keep unmatched rows with LEFT JOIN and COALESCE

An inner join drops customers with no orders. A left join keeps them, and COALESCE replaces the resulting NULL with 0.

SQL
SELECT
    c.customer_id,
    c.name,
    COALESCE(SUM(o.amount), 0) AS total_spent
FROM customers AS c
LEFT JOIN orders AS o
    ON o.customer_id = c.customer_id
GROUP BY c.customer_id, c.name
ORDER BY total_spent DESC;

Habits that prevent wrong answers

  • Check the grain of each table (one row per what?) before joining, to avoid duplicated rows that inflate sums.
  • Count with COUNT(DISTINCT ...) when the same entity can appear many times.
  • Remember that NULL is ignored by most aggregates and never equals anything, including another NULL.
  • Reconcile a total against a simple query before building on it.
